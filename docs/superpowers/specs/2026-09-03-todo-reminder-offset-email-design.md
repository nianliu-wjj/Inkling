# 待办提醒：相对偏移下拉 + 邮箱提醒方式

**日期**：2026-09-03
**状态**：待实现

## 背景

当前待办提醒由两个日期时间输入（提醒日期 + 提醒时间）设置绝对时刻，留空则走默认三次提醒
（`domain/todo.rs` 的 `default_reminder_slots`：前 30 分钟 / 前 5 分钟 / 到点）。
问题有两个：填两个字段才能设一次提醒，操作成本高于它的价值；提醒只能是桌面弹窗，
用户离开电脑就收不到。

## 目标

1. 提醒时间改为下拉框选择**相对完成时间的偏移**，默认前 15 分钟。
2. 提醒方式支持**桌面弹窗**与**邮箱**，可同时启用。
3. 邮件通过用户自配的 SMTP 发送，应用不依赖任何自建服务端。

## 非目标

- 不做 QQ 机器人等其他渠道。渠道抽象要留出扩展位（见「渠道扩展」），但本轮只实现弹窗与邮件。
- 不做邮件模板自定义、不做提醒历史查看页。

## 需求细节

### 提醒时间

下拉框选项，共 7 项：

| 显示文案 | 偏移分钟 |
|---|---|
| 不提醒 | `NULL` |
| 前 15 分钟 | 15（默认） |
| 前 30 分钟 | 30 |
| 前 1 小时 | 60 |
| 前 3 小时 | 180 |
| 前 6 小时 | 360 |
| 前 1 天 | 1440 |

**存相对偏移，不存绝对时刻**：修改完成时间后提醒时刻自动跟随，无需额外同步逻辑，
也不会出现「改了截止时间，提醒还停在旧时刻甚至落到完成时间之后」的情况。

### 提醒次数

每条待办提醒**两次**：

1. **偏移提醒**：`due_at - offset`
2. **到点兜底**：`due_at`

选「前 1 天」时不会遗漏到期。选「前 15 分钟」时两次提醒相隔较近，这是用户自己选的偏移
所决定的，不做特殊处理。选「不提醒」时两次都不触发。

现有的「前 30 分钟 / 前 5 分钟 / 到点」默认三次计划**移除** —— 下拉框选一个值的语义是
一个偏移，保留一套隐式的三次计划会让「我选了前 1 小时，为什么前 5 分钟也响了」无法解释。

### 提醒方式

两个独立勾选，可同时启用、也可都不选（等价于不提醒）：

- **桌面弹窗**：默认勾选，行为不变（右上角提醒卡片窗口）
- **邮箱**：默认不勾选，逐条待办勾选

勾了邮箱但 SMTP 未配置时，保存拦截并提示前往设置页配置。

### SMTP 配置

在偏好设置页新增「邮件提醒」分区：

| 字段 | 说明 |
|---|---|
| `smtp_host` | 如 `smtp.qq.com` |
| `smtp_port` | 默认 465 |
| `smtp_tls` | 是否启用 TLS，默认开 |
| `smtp_username` | 登录账号 |
| `smtp_password` | **应用专用密码**，非邮箱主密码 |
| `smtp_from` | 发件人地址 |
| `smtp_to` | 收件人地址 |

附「发送测试邮件」按钮，便于配置后立即验证，不必等到提醒到点。

## 架构

### 数据层：迁移到 v3

`todos` 表新增三列：

```sql
remind_offset_minutes INTEGER              -- NULL = 不提醒
remind_desktop        INTEGER NOT NULL DEFAULT 1
remind_email          INTEGER NOT NULL DEFAULT 0
```

`remind_at` 列**保留但语义变更**：不再存用户设置的提醒时刻，改由 `due_at - offset` 现算。
该列仅在 `repeat_rule` 推进时作为游标使用，避免为重复提醒再引入一张表。

**存量迁移**：所有待办统一置为 `offset=15, desktop=1, email=0`，并清空 `remind_at`。
原本手动设过具体提醒时刻的待办会丢失那个时刻 —— 这是有意的取舍：就近归类到六个档位会
产生「我设的 18:40，现在变成 18:45」这种静默偏移，比统一归为默认值更难解释。

### 设置层

`domain/models.rs` 的 `Settings` 新增上述七个 SMTP 字段，走既有的 `settings` 键值表
（与快捷键、主题同一张表，本地单机应用的既有存储方式）。

**密码处理**：`settings_get` 返回时把 `smtp_password` 替换为固定掩码常量，避免密码进入
前端状态、日志与事件广播。`save_settings` 收到掩码值时保留数据库中的原值，收到其他值
才更新 —— 这样前端不需要持有真实密码也能保存其他设置项。

### 服务层

新增 `services/mailer.rs`：

- 用 `lettre` crate 发信（Rust 生态标准 SMTP 客户端）
- **独立发信线程 + 队列**：调度器不能同步发邮件。`tick()` 持着数据库锁，
  SMTP 握手可能耗数秒，同步发送会卡住整个提醒扫描
- 失败重试 3 次（指数退避），仍失败则记日志放弃，不阻塞后续提醒

`services/reminder.rs` 的 `tick()` 改造：

```
for 每条待办:
    offset = todo.remind_offset_minutes
    if offset is None: continue          # 不提醒

    for (when, slot) in [(due - offset, "offset"), (due, "due")]:
        if when > now: continue
        if todo.remind_desktop: 派发到弹窗渠道
        if todo.remind_email:   派发到邮件队列
```

### 渠道扩展

幂等键从 `todo|slot|时刻` 扩展为 `todo|slot|渠道|时刻`。这既是为后续渠道（QQ 机器人）
留位，也解决一个当下的正确性问题：邮件发送失败重试时，若与弹窗共用一个幂等记录，
会被弹窗那次成功的记录挡掉而永不重发。

## 界面

`TodoEditorModal` 中两个提醒日期时间输入替换为一行：

```
提醒时间  [ 前 15 分钟  ▾ ]     提醒方式  ☑ 桌面弹窗  ☐ 邮箱
```

选「不提醒」时方式勾选置灰禁用。

`SettingsView` 新增「邮件提醒」分区，含七个配置字段与「发送测试邮件」按钮。

## 错误处理

| 场景 | 行为 |
|---|---|
| 勾邮箱但 SMTP 未配置 | 保存时拦截，toast 提示去设置页配置 |
| SMTP 认证失败 | 测试邮件按钮回显具体错误；提醒场景重试 3 次后记日志 |
| SMTP 连接超时 | 同上。队列不阻塞，后续提醒正常触发 |
| 偏移后时刻早于当前 | 到点兜底仍会触发；偏移那次因已过期被跳过 |

## 测试

**Rust 单元测试**（`domain/todo.rs`）：
- 偏移计算：各档位得出正确的提醒时刻
- 幂等键含渠道后，同待办同时刻的弹窗与邮件互不冲突
- `offset=NULL` 时不产出任何提醒槽位

**迁移测试**：v2 数据库升到 v3 后，存量待办均为 `offset=15, desktop=1, email=0`。

**实机验证**：
- 「发送测试邮件」按钮走通 SMTP 链路
- 建一条 1 分钟后到期、勾选邮箱的待办，确认弹窗与邮件都到达

验证需要真实 SMTP 凭据（主机 / 端口 / 账号 / 应用专用密码 / 收件邮箱），
仅写入本地数据库，不进仓库、不回显在输出中。
