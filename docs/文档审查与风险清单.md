# Inkling 文档审查与风险清单

> **审查日期**：2026-08-29
> **审查范围**：`doc/Inkling（念头捕手）需求规格说明书.md`、`doc/Inkling 架构设计文档.md`、原型 `doc/index.html` / `doc/app.js` / `doc/styles.css`。
> **本轮限制**：只审查和修改文档，不修改原型代码，不进行功能编码。

## 1. 本轮结论

项目目前可以进入“需求与架构收敛”阶段，但**不应直接开始编码**。原需求与架构存在多处版本、数据模型、窗口模型和统计口径不一致；原型能够辅助交互走查，但不能证明后端能力已实现。已将确定性问题直接修正文档，仍需在编码前完成本清单中的验收口径确认。

| 优先级 | 问题 | 影响 | 处理结果 |

## 3. 编码前仍需冻结的规则

这些事项已在文档中显式标为约束或风险，但需要产品/设计确认后才能作为最终验收标准：

1. **重复提醒的边界**：本轮文档选择“只重复提醒、不自动复制待办”；若产品希望重复生成待办，必须另行定义新待办的 ID、父子关系、计划完成时间、标签/备注复制和完成行为。
2. **历史补录的时间校验**：普通创建禁止过去时间；历史日期“新增待办”允许补录，但提醒时间是否允许过去、是否立即弹出提醒，需要固定规则。
3. ~~**已完成父待办新增子任务**：当前保留为唯一例外，并要求原子地恢复父待办为未完成、清空 `completed_at`；若产品不接受历史完成状态被重开，需要改为创建新父待办或禁止该操作。~~ 已确认采用方案 B：允许该操作，并在同一事务内将父级重开、清空 `completed_at`，将父级 `due_at` 顺延为 `max(原父级 due_at, 新子任务 due_at)`。
4. **优先级变更交互**：已确认采用锚定式三选一 popover，当前项明确选中，父子优先级独立，变更只更新 `priority/updated_at`，不触发统计。
4. **删除语义**：已完成项目前文定义为不可删除；需要确认是否允许用户在数据导出/清理中永久删除，及父待办删除时子任务的级联策略。
5. **剪贴板图片/富文本大小上限**：需求只写“统一 SQLite”，架构已预留附件文件引用；需确认上限、保留期限和备份/导出行为。
6. **日期详情中的待办归属**：当前按计划完成日期展示；如果用户希望按实际完成日期展示已完成项，应增加单独筛选或双时间轴。
7. **权限与不可用场景**：macOS 辅助功能/全局快捷键/剪贴板权限、Windows 透明窗口和自启动被策略禁用时的提示、降级与恢复流程尚未写成验收用例。

## 4. 原型走查发现（仅记录，不改代码）

- 原型数据存于内存，刷新即丢失；“已同步回数据库”和“原型中无法真的退出”属于演示文案，不能作为实现承诺。
- 原型依赖 CDN GSAP，与正式 CSP 冲突。
- 原型模拟托盘、桌面、提醒、置顶浮窗和窗口层级，不能验证系统级行为。
- 原型中时间是本地字符串，跨午夜/时区/夏令时场景不能验证正式实现的时间模型。
- 原型当前新增子任务时只重置父级 `done/doneAt`，尚未同步更新父级计划时间；这与已确认的方案 B 存在差异，本轮不修改原型代码，正式实现前需按文档补齐。
- 原型当前优先级菜单按当前值拆成上/下两个阶梯组，并省略当前选项；本轮仅将优化后的交互写入需求与架构文档，不修改原型代码，正式实现前需按新规则重做。
- 原型的静态种子数据用于展示逾期、子任务和热力图，不能作为真实统计数据或业务数据迁移样例。

## 5. 后续审查门槛

在允许编码前，至少要完成：

- 需求文档与架构 SQL/事件/窗口矩阵逐项对照，无旧字段和旧文件名残留；
- 提醒、逾期、重复提醒、历史补录、完成/重开状态形成状态转移表；
- 多屏、时区、夏令时、应用重启、数据库/附件写入失败形成异常流程；
- 将本清单中的“编码前仍需冻结”逐项改为“已确认”或记录明确的产品决策；
- 原型与正式实现边界在 README 或交付说明中保持一致。
