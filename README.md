# Inkling（念头捕手）

> 一个“安静待命、快速捕获、随时归档”的桌面效率工具：把转瞬即逝的念头、剪贴板内容和待办事项收集到同一个本地工作流中。

- **当前阶段**：Rust + GPUI 功能实现阶段（已接入 SQLite 持久化、三视图、剪贴板捕获、待办树、统计、搜索、导出与偏好设置）
- **审查基线**：2026-08-29
- **README 编写日期**：2026-08-30
- **目标平台**：macOS、Windows
- **实现路线**：保留当前 Rust + GPUI 桌面架构，按需求规格和架构设计逐阶段补齐功能

> ⚠️ `doc/index.html` 仍是用于视觉和交互走查的静态原型，不代表原型中的所有平台能力都已在正式程序中实现。正式程序以 Rust + GPUI 代码、需求规格说明书和架构设计文档为准；原型仅用于交互验收。

## 项目简介

Inkling 面向需要随手记录和整理信息的桌面用户，核心目标是减少“想到—记录—整理”之间的摩擦：

1. 通过顶部中央的悬浮面板快速输入，不打断当前工作；
2. 在笔记、剪贴板和待办三种模式之间快速切换；
3. 使用本地 SQLite 统一保存结构化数据；
4. 对大体积笔记和剪贴板附件采用应用数据目录中的文件存储；
5. 通过历史归档、日期详情、热力图和趋势数据回看近期活动；
6. 通过托盘、全局快捷键和开机静默启动保持“随时可用、但不打扰”。

## 核心体验

### 1. 顶部悬浮捕获

- 顶部透明感应区常驻，不依赖高频鼠标位置轮询；
- 鼠标触顶或全局快捷键呼出面板；
- 面板使用滑入/滑出动画，失焦后按设置立即、延迟或固定时长收起；
- 目标是从呼出到可输入尽量控制在 1 秒内。

### 2. 三态快速切换

- **笔记**：即时渲染 Markdown，支持草稿自动保存、标签和归档；
- **粘贴板**：捕获文本、图片、URL、代码片段等内容，支持搜索、编辑、置顶和收藏；
- **待办**：支持完成时间、提醒、优先级、标签、备注、逾期和子任务树。

### 3. 单窗口归档

主窗口采用左右结构，笔记归档、剪贴板归档、待办归档、统计和偏好设置均在同一个 `main` 窗口内切换，不为统计或设置额外创建业务窗口。

### 4. 本地优先

数据默认保存在本机应用数据目录，不依赖云端服务，不主动进行遥测上报。用户可以在设置中打开数据目录并执行备份/导出。

## 产品功能范围

### 笔记捕获与归档

- 支持 Markdown 轻量即时渲染；
- 输入停止 500ms 后保存草稿；
- 草稿使用稳定 ID，归档成功后从草稿状态提升为正式笔记；
- 内容不超过 1MB 时直接存入 SQLite；
- 超过 1MB 时写入应用数据目录 `notes/`，SQLite 保存元数据和相对路径；
- 标签作为独立元数据维护，不解析正文中的 `#tag`；
- 文件写入采用临时文件和原子替换，失败时保留可恢复状态。

### 剪贴板捕获

- 监听文本、图片、URL、代码等内容；
- 计划使用 500ms 轮询捕获系统剪贴板；
- 使用 SHA-256 哈希进行去重，并抑制应用自身写回内容造成的回声记录；
- 支持搜索、编辑、复制、双击粘贴并置顶、收藏；
- 默认保留 30 天，具体清理策略由偏好设置控制；
- 大型图片或富文本附件需要在编码前冻结大小上限、保留期限和导出策略。

### 待办与子任务

- 一个顶级待办最多 5 个子任务；子任务不可继续嵌套；
- 待办和子任务统一使用内容、计划完成时间、提醒、优先级、标签、备注等字段；
- 计划完成时间在数据层使用 `due_at`，实际勾选完成时刻使用 `completed_at`；
- 未完成且 `due_at` 已经过去的事项标记为逾期；
- 父待办存在逾期子任务时，父待办及整棵子任务树进入逾期区；
- 所有子任务完成后，父待办自动完成；
- 已完成项默认禁止修改、删除和取消完成。

### 优先级选择器

优先级变更已从原型中的上下阶梯菜单优化为**锚定式三选一 Popover**：

- 菜单始终展示“高 / 中 / 低”三个选项；
- 当前选项以勾选、描边和选中状态明确标识；
- 颜色和文字同时使用，不能仅依赖颜色识别；
- 默认在优先级徽章下方打开，空间不足时翻转到上方；
- 支持鼠标、键盘、`Esc` 和点击外部关闭；
- 父待办与子任务的优先级相互独立，不级联修改；
- 修改只更新 `priority` 与 `updated_at`，不改变完成时间、提醒、状态、标签或备注；
- 保存成功后按计划完成时间、优先级、创建时间稳定重排；
- 已完成项只显示非交互式徽章。

### 已完成父待办新增子任务

这是已完成项允许操作的唯一例外：

1. 已完成父待办仍可新增子任务；
2. 新子任务默认为未完成，计划完成时间默认为当前时间后 1 小时；
3. 新子任务不受“计划完成时间不得晚于父级”的限制；
4. 同一事务内插入子任务、将父待办恢复为未完成、清空 `completed_at`；
5. 父待办的计划完成时间更新为：

   ```text
   max(原父待办 due_at, 新子任务 due_at)
   ```

这样可以避免父待办因沿用已过去的计划时间，在刚被重新打开后立即显示为逾期。

### 提醒

- 未指定提醒时，默认在计划完成时间前 30 分钟、前 5 分钟和到点各提醒一次；
- 指定提醒后，仅在指定时刻提醒；
- 重复提醒只重复提醒计划，不自动复制新的待办；
- 用户可以从提醒卡片选择下一次提醒时间；
- 调度器需要记录已触发的提醒实例，避免应用重启或轮询导致重复弹出；
- 提醒以应用自定义右上角卡片展示，而非直接依赖系统通知。

### 统计与热力图

- 笔记按成功归档计数；
- 粘贴板按成功捕获的新条目计数；
- 待办分别记录创建事件和实际完成事件；
- 待办总数按计划完成日期统计，完成数按 `completed_at` 统计，逾期数按查询时刻从业务数据推导；
- 统计事件必须幂等，应用重启、重复事件或编辑事项不能重复累加；
- 热力图中的“pin”仅为类别标识，不代表置顶状态。

## 关键业务规则

| 领域 | 当前规则 |
| --- | --- |
| 待办时间 | 界面称“完成时间”，数据层使用 `due_at` 表示计划完成/截止时间 |
| 实际完成 | 用户勾选时记录 `completed_at`，完成后事项沉底 |
| 子任务数量 | 顶级待办最多 5 个子任务，子任务不可嵌套 |
| 子任务时间 | 普通场景下子任务 `due_at` 不得晚于父级；已完成父级新增子任务时例外 |
| 优先级 | 高、中、低；同计划时间时高优先级在前；父子优先级独立 |
| 已完成项 | 不允许编辑、删除、改优先级、改提醒、改时间或取消完成；已完成父级可新增子任务 |
| 逾期 | 未完成且 `due_at` 已经过去即逾期；历史日期中的未完成事项均视为逾期 |
| 数据位置 | 默认使用应用数据目录，不写安装目录或源码目录 |
| 大文件 | 笔记超过 1MB 时落盘到应用数据目录 `notes/` |
| 窗口 | `main` 承载归档、统计和设置；`panel` 为高优先级悬浮捕获层 |

## 目标技术架构

正式实现采用以下技术架构：

```text
Rust + GPUI
├─ app：主窗口、侧边栏、统计和设置视图
├─ panel：顶部悬浮捕获面板
├─ views：笔记、剪贴板、待办及日期详情
├─ store：SQLite WAL、事务、标签、统计和文件落盘
├─ summon：全局快捷键、触顶感应、剪贴板轮询
├─ settings：主题、失焦、保留策略、自启动和备注偏好
├─ stats：日期网格、热力图、趋势和业务聚合
└─ platform：Windows/macOS 窗口、剪贴板和系统能力适配
```

计划使用：

- Tauri 2：桌面窗口、托盘、系统集成；
- Rust：核心业务和平台能力；
- Vue 3 + TypeScript：正式前端界面；
- Vite：构建与按视图分包；
- UnoCSS：轻量样式体系；
- GSAP：面板和浮层动画；
- SQLite + `rusqlite`：本地结构化存储；
- ProseMirror：笔记编辑和即时渲染；
- ECharts：热力图与趋势图；
- Vitest / Cargo test：前端与 Rust 测试。

架构遵循两个边界：

> 渲染进程不直接碰 SQL，Rust 不直接碰 DOM；domain 层不依赖 Tauri，可脱离框架进行单元测试。

## 数据与隐私边界

### 计划中的核心数据

- `notes`：笔记、草稿、归档状态和文件引用；
- `tags` / `note_tags`：笔记标签；
- `clipboard_entries`：剪贴板条目、类型、哈希和附件引用；
- `todos`：待办、子任务、时间、状态、提醒、优先级和备注；
- `todo_tags`：待办标签；
- `activity_events`：幂等活动事件；
- `stats_daily`：每日聚合统计；
- `settings`：本地偏好设置。

### 存储原则

- 默认保存到操作系统应用数据目录；
- 不默认写入项目安装目录或源码目录；
- SQLite 使用 WAL 模式；
- 大文件使用临时文件 + 原子替换；
- 数据库记录与外部文件引用需要具备失败恢复能力；
- 用户可以导出或备份本地数据；
- 不把置顶状态误当作活跃度统计；
- 不在 README 或产品文档中承诺当前尚未实现的云同步能力。

## 原型与正式实现边界

| 能力 | 当前静态原型 | 正式实现目标 |
| --- | --- | --- |
| 数据保存 | JavaScript 内存种子数据，刷新后丢失 | SQLite 持久化、迁移和失败恢复 |
| 笔记草稿 | 模拟“已暂存 SQLite”提示 | Rust IPC + SQLite 草稿表 |
| 剪贴板 | 页面逻辑/示例数据模拟 | 真实系统剪贴板监听、哈希去重和清理 |
| 系统托盘 | 页面上的模拟菜单 | Tauri Tray，适配 macOS/Windows |
| 全局快捷键 | 原型内模拟触发 | 系统级快捷键注册和冲突处理 |
| 窗口层级 | HTML 区块模拟 | Tauri 多窗口、always-on-top、焦点和失焦策略 |
| 多屏定位 | 无法验证系统工作区 | 基于显示器 work area、DPI 和逻辑坐标定位 |
| 提醒 | 演示按钮触发 | 调度器、提醒实例幂等和重启恢复 |
| 优先级菜单 | 当前为上下阶梯菜单 | 锚定式三选一 Popover，当前值明确选中并支持键盘 |
| 已完成父级新增子任务 | 仅重置内存中的完成标记 | 事务内新增子任务、父级重开并顺延 `due_at` |
| 统计 | 固定种子数据和演示图表 | 活动事件幂等写入、每日聚合和业务数据查询 |
| 退出 | 显示“原型中无法真的退出”提示 | 托盘菜单中的真实退出和资源清理 |

原型仅用于：

- 视觉层级和布局走查；
- 动画节奏和交互路径走查；
- 卡片信息密度和悬浮按钮走查；
- 需求讨论和验收场景示意。

原型不能作为以下能力的验收依据：

- 持久化和数据库迁移；
- 系统权限和平台 API；
- 多屏、DPI、时区和夏令时；
- 文件写入失败与恢复；
- 提醒去重、应用重启恢复；
- 性能指标和安全策略。

## 当前实现边界

项目已经进入 Rust + GPUI 编码实现阶段。需求与架构文档仍是验收基线；新增行为必须先同步文档，再进入代码。当前已实现和仍待补齐的边界如下：

### 1. 需求与架构对照

- 已完成 SQLite 初始化、迁移、核心业务表和活动统计模型；
- 已完成笔记、剪贴板、待办、标签、优先级、搜索、统计、归档和导出基础闭环；
- 已将正式实现架构统一为 Rust + GPUI，静态原型只作为视觉与交互验收参考；
- 仍需在平台能力补齐后，对窗口矩阵、权限降级、多屏 DPI 和时区规则进行回归验证。

### 2. 已落地的状态规则

- 待办创建时校验层级、子任务数量和父子计划时间；
- 已完成待办不可重开、编辑或删除；
- 完成最后一个子任务时，父任务自动完成；
- 已完成父待办允许新增子任务，新子任务创建后父待办恢复为未完成；
- 删除未完成父待办时，子任务在数据库和内存中级联删除；
- 优先级、标签和搜索均使用统一的持久化字段与规则。

### 3. 仍待补齐的异常流程

需要明确并写入验收用例：

- 多显示器、DPI 缩放、工作区边界和显示器热插拔；
- 用户时区变化、跨午夜、夏令时和多设备数据；
- 应用重启期间的提醒、草稿和数据库事务；
- SQLite 写入失败、数据库迁移失败；
- 大文件写入失败、文件丢失或路径不可写；
- macOS 辅助功能/剪贴板权限和 Windows 窗口策略被禁用；
- 全局快捷键冲突及能力降级。

### 4. 仍待补齐的内容与平台能力

- 图片、富文本和其他剪贴板附件的捕获、落盘、预览与导出；
- 待办日期/时间选择器、提醒调度、重复规则和备注/标签编辑器；
- 笔记完整 Markdown 编辑器、剪贴板编辑器和链接打开；
- 系统托盘、置顶悬浮窗、自定义快捷键录制和跨平台通知；

## 贡献与变更约束

在项目正式开发过程中，任何需求或架构变更都应遵循以下顺序：

1. 先更新需求规格说明书；
2. 再同步架构设计、数据模型和时序；
3. 更新文档审查与风险清单；
4. 检查原型是否需要同步调整，并明确记录原型与正式实现差异；
5. 所有未冻结的规则不得直接转化为代码假设。

当前阶段的变更范围限定为：

- 先补充需求、架构或验收文档，再修改 Rust + GPUI 实现；
- 每完成一个可验证阶段，使用中文提交信息分批提交到本地仓库；
- 不将静态原型中尚未落地的平台行为误判为已实现能力；
- 对尚未补齐的 P3 能力保持明确边界，避免以占位 UI 代替真实行为。
